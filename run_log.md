This inference is deliberately **not** applied in Phase 3: a `session_incomplete` result there is often caused by baud/link instability rather than a deterministic compute limit, and may not recur if the cable or port is fixed before the next attempt. Phase 3's raw/meta write order was also swapped (raw now written before the terminal `session_log` row, matching Phase 2's already-safer order) so the same orphan-detection logic works identically there. Default is resume-on; `--fresh`/`--no-resume` archives the existing CSVs (timestamped rename, never deletes) and starts counting from zero.
