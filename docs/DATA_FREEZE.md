# Data freeze v1: dataset, selection and analysis rules

Generated by `analysis/phase4/data_freeze.py` (`make freeze`); do not edit by hand. Constants and tables are read from the code and from `data/raw/**/sessions.csv`; the wording of the rule table and the before/after labels are written by hand from the git history and the Phase 4 report (section 4), and are marked **OBSERVED** (checkable in the files or in `git log`) or **INTERPRETATION** / **UNVERIFIED**.

## 1. What is frozen

- `data/raw/`: 458 files; `data/derived/`: 25 files (the manifest itself excluded); 6.5 MB together. `data/derived/MANIFEST.sha256` lists the sha256 of every one of them (`shasum -a 256 -c data/derived/MANIFEST.sha256` from the repository root; `analysis/phase4/data_freeze.py --check` does the same). sha256 of the manifest file: `3dad5a7ef1cf7165621f8e68141ee57ef0c7e04d8e52bb2df81dc976ff522abe`.
- Phase 2 and 3 collection: 70 sessions (one env sidecar each), starting 2026-10-04 to 2026-10-31 (UTC). Phase 1 (PC build against Qiskit Aer): 3 infidelity files (20261003T111917Z, 20261004T091042Z, csv).
- Nothing under `data/raw/` or `data/calibration/` is written by any analysis script (`analysis/common/sessions.py` and `analysis/phase4/audit.py` read only). `data/derived/` is rewritten by `analysis/reproduce.py`, which prints the sha256 of every figure, table and the report so two runs can be compared.
- What the freeze does **not** claim: that the rules below were set before the data were seen (most were not, section 3), or that the board data are correct (the reference counter is uncalibrated, section 3).

## 2. Scope and session selection

Scope (`analysis/common/sessions.py`): boards Uno R3, ESP8266, ESP32; circuits h_all, bell_ghz, qft, grover; n >= 2; Phase 2 has no data at or beyond its wall; Phase 3 is kept up to the Phase 2 wall n of the board (Uno R3 n=8, ESP8266 n=13, ESP32 n=14; `config/sweep_ranges.toml [wall.<board>]`). qpe and steane_encode are not used. Bucket `with_ref` = original collection; `with_ref_<TAG>` = repeat session (`pc/run.py --rerun TAG`), a whole new sample per point, never merged with another bucket. Replaced and replicate sessions are used only for the reproducibility table (`SES.replicates()`) and for the Phase 3 PC-simulation band (offload_band.py, in-scope n only).

## 3. Rules in force and when each was set

Reference points: the original data were committed 2026-10-04 to 2026-10-10 (`git log -- data/raw`, Phase 2/3 sessions starting 2026-10-04); the first Phase 4 analysis commit is `bf9b692` (2026-10-29 20:20 +0700); the fix round that changed the rules, after the first test scores were known, is `0724ab3` (, 2026-10-29 22:30 +0700). The repeat sessions r2, r2b, r2c were collected 2026-10-30/31 *after* those scores. 'Before the data were seen' therefore never applies to the Phase 4 rules: the question per rule is whether it was set before the **scores** (the held-out errors) were seen.

## 4. Tag

The tag is **not** created by the scripts. After committing `docs/DATA_FREEZE.md` and `data/derived/MANIFEST.sha256`:

```
git tag -a data-freeze-v1 -m "data freeze v1: data/raw and data/derived as listed in data/derived/MANIFEST.sha256; rules of docs/DATA_FREEZE.md" <commit>
```

`git tag` is local; nothing here is pushed. To verify later: `git checkout data-freeze-v1 && shasum -a 256 -c data/derived/MANIFEST.sha256`.
