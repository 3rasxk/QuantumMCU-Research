## Interpretation (not tested)

- The fitted slope (1.25 doublings per qubit) is above the 1.00 reference (cost proportional to the 2^n amplitudes at a fixed gate count). For circuits whose gate count grows with n (qft, grover) a slope above 1 is what a growing gate count would give; a fixed per-call overhead at small n or memory effects at large n would also move it. None of these readings was tested here (`analysis/phase2_gate_cost_fit.py` fits a gate-cost model).
- Offload overtakes local execution from n=5 in the measured range; this compares a local run of the circuit with a serial round trip whose cost is dominated by the PC simulation at larger n, so it says where offloading pays on this link, not that the board is slower at the circuit itself.
- Where the counter comparison exists, micros() reads -2.67 to -0.511 % relative to the counter; relative to this uncalibrated counter only. Differences of a few microseconds at small n are at the resolution of micros() on the board.

## Limitations

- One unit of each board (one Uno, one ESP8266, one ESP32); no unit-to-unit spread is measured.
- One run per point set (100 reps per point, fewer where the 2 h per-point cap stopped a point); no run-to-run spread.
- `micros()` times the window the firmware defines around the circuit call (see `firmware/*/src/main.cpp`); the
  contents of that window were not re-verified here. The Uno's `micros()` has 4 us resolution.
- The ESP32 counter was only self-loopback tested and is not externally calibrated; a +17.5 +/- 1.9 ppm calibration
  against the PC clock exists (`data/calibration/counter_20261004.json`) but is not stored in the session sidecars.
  Counter differences are relative to this counter.
- Sessions of one point set can come from several git commits (named on each chart); the working tree was dirty during
  collection, so the exact code state of some sessions cannot be reconstructed.
- Phase 3 times include a PC-side Qiskit Aer simulation of the circuit; the board only times the round trip.
